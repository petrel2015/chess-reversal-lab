# 悔棋与回看

## 概述

悔棋与回看让玩家对进行中的推演拥有主导权：悔棋/恢复以*完整回合*为单位（你的着法 + 引擎的应手），另有独立的只读回看模式逐半步浏览全局而不触碰实际对局。

## 背景

人机推演本质是试错过程——你尝试某种攻法、被 refutation 击退，然后只想修正那一步决策，而不是整个重摆重下。

## 问题

半步悔棋在这里是错误的粒度。只撤自己的半步会把对局停在引擎回合、且没有它的应手可撤；若让引擎重新应答，"换一手试试"的成本和困惑都会增加。朴素的时光倒流还容易把为旧局面算出的引擎应答错误地套到新局面上。

## 目标

- 一个动作就回到*你的*决策点，并连带撤销引擎的应手。
- 恢复原样重放该回合；确实又轮到引擎时，诚实地重新计算。
- 对局中任何时刻都能瞬时查看更早盘面，且对真实局面零风险。
- 打断进行中的搜索（通过悔棋）必须安全。

## 不解决的问题

该功能主动不做：

- 半步粒度的撤销
- 原地修改历史（要分叉请先悔棋）
- 多变体树或命名变例
- 跨页面刷新的历史持久化

## 解决方案概述

直接构建在 chess.js 状态之上：

- **悔棋**连续弹出着法，直到撤掉一个己方着法（其下方的引擎应手随之出栈），并把弹出的这对着法压入恢复栈。
- **恢复**用 `chess.move` 原样重放栈顶那一对。若重放后又轮到获胜方行棋（即你只重放到自己那半步），则消费该栈条目但丢弃旧应答——由引擎现场重算。
- **回看**维护指向 `moves[]` 的游标 `reviewPly`；展示盘面从开局快照重建（`startingPositionRef` + 带正确易位标记的 FEN），因此权威的活动 `Chess` 实例在回看期间绝不会被改动。

## 详细行为

- 你至少走过一步后悔棋才可用；每按一次撤一个完整回合。
- 引擎思考中按悔棋会先发 UCI `stop`；迟到的 bestmove 随后被过期 FEN 闸门拦下并丢弃（其评分仍可并入评估展示）。
- 恢复精确重放被撤内容，包括升变（固定后）。
- 回看 ←/→ 在 0…n 半步间行走；游标 < n 时，棋盘、最近一步高亮、面板子力与胜算条都反映历史局面；横幅显示"正在回看 x/y 步"。
- 回看时尝试落子会被拒绝并给出指引，而不是静默切换模式。

## 用户体验

所有控件集中在棋盘下方的分组里（"改变棋局"：悔棋/恢复 · "回看棋谱"：上一步/下一步），不可用时按钮禁用——没有隐藏陷阱。

## 兼容性与历史影响

无历史行为受影响；随 v0.1.0 上线。它与摆棋/重置流程是组合关系而非改动关系（"重摆开局"回到赛前快照；"从当前局面重摆"把实时局面变成可编辑设置并保持正确行棋方）。

## 数据与隐私影响

历史仅存于内存（`moves`、`redoTurns`）；本功能不引入持久化或数据传输。

## 性能影响

每次回看游标变化最多重放 n 步经 chess.js 重建盘面——在正常对局长度下开销可忽略。

## 当前限制

- 没有分叉树：连撤两手后走出新着法，原变化线即永久丢弃。
- 刷新即清空历史（无持久化，与项目隐私取向一致）。
- 回看不支持任意拖动进度条，只能逐半步行走。
