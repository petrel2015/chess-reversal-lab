# 引擎驱动对局

## 概述

引擎驱动对局让 Stockfish 17.1（单线程 WASM）执用户指定的获胜方，在 Web Worker 内经 UCI 协议搜索并永远走出它认为最佳的着法；滑块控制每步思考时长。

## 背景

"多子优势"要变成"真能赢下来"，必须面对最强防守的练习。一个故意示弱或随机的对手会毁掉工具的价值。

## 问题

浏览器跑不了原生分析程序；多数云端引擎服务需要账号/令牌且每一手都有网络往返；朴素的 WASM 内嵌又容易在做深搜索时冻住 UI 线程。

## 目标

- 零安装、零账号、完全客户端运行的对手引擎。
- 绝不阻塞交互：搜索必须离开主线程。
- 节奏可预期：用户可见的单步思考时间 0.4–3.0 秒。
- 中断下的正确性：思考中悔棋时，绝不能把针对已消失局面算出的应答落到棋盘上。

## 不解决的问题

该功能主动不做：

- 多续着（MultiPV）分析或残局表查询
- 多核并行或大 NNUE 配置
- 难度分级或故意失误——指定一方永远全力求胜
- 开局库或残局表（syzygy）导入

## 解决方案概述

`app/lib/use-engine.ts` 为整个页面生命周期只创建一个 `Worker('/engine/stockfish.js')`：

```text
uci ─▶ uciok ─▶ setoption Hash 32 ─▶ isready ─▶ readyok ⇒ 就绪
每回合: stop → position fen <fen> → go movetime <400–3000>
结果:  bestmove <uci> → moved | (none) | stale(仅保留评分)
```

三个关键决策：

1. **用 ref 而非依赖数组持有回调。** 频繁变化的回调一律经 ref 读取，React 重渲染绝不会重建 Worker；此前一旦在 WASM 编译中途重建，引擎就会永久卡在"载入中"（该问题曾短暂存在于 v0.1.0 区间内并很快修复）。
2. **过期搜索防护。** 每次搜索记录起始 FEN（`activeSearchFenRef`）。若 `bestmove` 返回时局面已经变化（用户悔棋等），该着法按*过期*丢弃，只把附带评分并入评估。仅这一道闸门就让"思考中悔棋"变得安全，无需 UCI `stop` 之外的任何取消协议。
3. **白方视角评分归一化。** 评分到达时以行棋方视角表示；统一变换为白方视角一次，让下游胜算计算只面对一致的参照系。

## 详细行为

- 触发条件：phase = playing、轮到获胜方、状态 = ready → 约 180 毫秒调度延迟 → `go movetime <滑块毫秒>`（默认 1200）。
- 应用返回的 UCI 串落子时升变固定为后。
- `(none)` 应答会上抛"无着法"结果，而不是无限等待。
- 评估文案按 ±0.6 / ±2.5 兵值分档，杀棋分单独表述（"可强制将死 · M5"）。
- 引擎故障进入错误态；摆棋仍可用，但 AI 对局停止。

## 用户体验

顶栏胶囊依次表达：载入中 → 已就绪 → 思考中 → 不可用。回合横幅声明当前谁走；评估文案始终以指定获胜方视角措辞。

## 兼容性与历史影响

无历史行为受影响；属奠基版本的一部分。Worker 生命周期修复只改内部实现，不改变任何外部可见行为。

## 数据与隐私影响

引擎在本机同源 WASM 内运行；搜索过程不向设备外发送任何内容。

## 性能影响

搜索占用一个 Worker 线程和 32 MB 置换表；主线程保持空闲。每步 3 秒上限是出于节奏设计，而非平台限制。

## 当前限制

- 单线程构建：即使多核设备也没有并行搜索。
- 没有持久的棋力/难度参数。
- 置换表固定 32 MB；超长会话不会自适应扩容。
