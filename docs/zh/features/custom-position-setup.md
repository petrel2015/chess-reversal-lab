# 自定义残局摆设

## 概述

自定义残局摆设是本工具的核心编辑体验：用户从空棋盘或标准开局出发，借助按颜色分组、带数量上限的棋子库，以点按或拖拽方式搭建任意合法局面；合法性校验持续运行并控制开始按钮。

![正在搭建后单杀黑王的残局](../../img/custom-endgame-setup-zh.webp)

## 背景

本工具为回答"假如"类问题而生，因此"构造局面"必须是第一操作，而不是藏在 FEN 导入后面的附属功能。

## 问题

在它出现之前根本没有对应产品：既有工具要么要求手输 FEN——对休闲学习者极不友好——要么把棋盘编辑器埋进为整局分析设计的厚重界面里。手机上的这类编辑器尤其难用。

## 目标

- 只靠点按就能完成拼局（移动端优先），同时提供拖拽（桌面便利）。
- 下棋约束在*编辑过程中*就执行，而不是等到开始时才拦截。
- 在自由摆法之外提供零思考成本的默认路径（标准开局）。
- 失败原因可见，而不是悄悄"纠正"输入。

## 不解决的问题

该功能主动不做：

- 解析或接受 FEN/PGN 输入
- 支持需要吃过路兵机会或特定易位历史的局面
- 提供有名目的残局/习题库
- 允许失衡或不合法的趣味摆法（一方两王、两王相邻、兵摆底线等）

## 解决方案概述

- 棋盘就是 React state 里一个 `{格子 → {颜色,类型}}` 的 map；编辑是纯 map 变换。
- 棋子库剩余数量由 `上限 − 当前数量` 推导，这意味着对局中被吃掉的子会自动回到可用额度——无需额外簿记。
- `boardToFen` 与 `validatePosition`（位于 `app/lib/chess-utils.ts`）在编辑期与开局期复用同一份代码，保证"校验通过的局面"就是"实际开下的局面"。
- 校验只返回翻译键；呈现方式（校验卡 + 开始按钮联动）由 UI 层决定。

## 详细行为

- 点选棋子库棋子 → 点击棋盘格放置；从库拖到格同样放置；从格拖回己方库即移除。
- 点击盘上棋子选中；点击另一格则移动，目标有子时交换位置。
- 约束即时生效：兵的排位规则、数量上限、只能放回己方颜色的库。
- 开始闸门条件：双方各一王；两王不相邻；第一/第八排无兵；非双方同时被将军；未行棋方不被将军。
- 预设：**空棋盘**清空一切；**标准开局**载入 32 子并保留易位权（`KQkq`）。载入后的任何手动修改都会把局面标记为自定义（易位 `-`）。

## 用户体验

状态栏对每个成功/被拒动作都有叙述（"白后被放到 c7…""兵不能放在第一排或第八排"）。侧面板的选中工具条为当前选中的盘上棋子提供取消 / 放回棋子库操作。

## 兼容性与历史影响

无历史行为受影响——它与首次发布同时上线，本身就是奠基性交互。URL、存储、输出格式在它之前都不存在。

## 数据与隐私影响

所有摆放数据只留在内存；任何摆设既不持久化也不上传。

## 性能影响

每次操作是一次 O(1) 的 map 更新外加每轮渲染一次 O(子数) 的校验扫描，在人类交互规模下可忽略。

## 当前限制

- 升变与易位历史语义按设计不可表达（见"不解决的问题"）。
- 无法复制粘贴或分享已搭好的局面。
- 数量上限严格等同标准棋具（例如不能像真实对局升变后那样摆出三个后）。
