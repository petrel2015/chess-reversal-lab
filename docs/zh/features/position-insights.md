# 局面洞察面板

## 概述

局面洞察面板是常驻的分析视图：双方子力明细、子力差，以及一条随对局演进明确标注估计来源的胜算条（按子力估算 → 引擎评估 → 回看半步 → 终局结果）。

## 背景

自定义局面的平衡性千差万别；没有实时读数，用户无法判断自己刚搭的局面是势均力敌、酷刑测试，还是白捡的胜局。

## 问题

原始引擎分（"+2.3"）对普通用户是一串密码，而纯子力计数又无视实际进程。只显示其中一个数字——或者在两者之间悄悄切换——都会让人把"估计"误当"保证"。

## 目标

- 一眼回答两个问题：谁子力更多？*此刻*谁更可能赢？
- 绝不把估计包装成事实：任何时刻都标注来源。
- 评估措辞始终采用场景自身视角（指定获胜方），而不是抽象的白/黑。
- 摆棋、对局、回看、终局四种状态下行为一致。

## 不解决的问题

该功能主动不做：

- 展示完整多续着（MultiPV）或主要变化线
- 提供逐手的引擎点评浮层
- 显示搜索深度/节点数
- 建模残局表的精确值

## 解决方案概述

- 子力明细来自对 `board` 的计数；差值套用固定价值（兵1 象3 马3 车5 后9），并对双方对称输出（`+3 / −3`）。
- 胜算 `W = 100 / (1 + e^(−cp/240))`，四舍五入并夹取到 1–99%，刻意除真实结果外永不出现 0/100：
  - 对局中有杀棋分：≈99/1
  - 对局中有 cp 分：上述 logistic 曲线
  - 首次评估前（或摆棋期）：同一曲线作用于 子力差×100
  - 回看中：按所查看历史半步的上下文重算
  - 终局：将死精确为 100/0，任意和棋为 50/50
- 评估文案分档（来自 `use-engine`）：以 ±0.6 与 ±2.5 兵值为阈值，杀棋单独措辞。全部文案按语言翻译。

## 详细行为

面板有两种摆放形态（摆棋/对局时在侧面板；布局允许时在棋盘下方出现紧凑条），CSS 决定每个断点恰好显示一个。回看期间即使实际对局继续，明细与胜算也跟随游标位置。

![对局进行中的面板](../../img/match-analysis-zh.webp)

界面本身带有估计免责脚注（"胜率为局面估算，不代表理论必胜……"）。

## 用户体验

无需任何配置——洞察是环境性的。来源标签同时承担了诚实的出处说明（"Stockfish 局面估算" vs "按当前子力估算"）。

## 兼容性与历史影响

无历史行为受影响；属 v0.1.0 奠基界面的一部分。

## 数据与隐私影响

纯内存状态上的计算；无持久化、无传输。

## 性能影响

每次棋盘变化经 memoization 做 O(子数) 重算，开销可忽略。

## 当前限制

- sigmoid 常数（240）是人工选择的启发值，非拟合数据。
- 战术局面下首次评估落地前，仅凭子力的估算可能与引擎结论差异明显。
- 除数量与价值外没有逐子的悬浮说明。
